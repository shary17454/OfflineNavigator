# خارطة الطريق

الحالة التفصيلية بندًا ببند موجودة في [`IMPLEMENTATION_PLAN.md`](./IMPLEMENTATION_PLAN.md).
هذا الملف ملخص عالي المستوى فقط.

## مكتمل فعليًا (مبني ومختبر حيًّا)

- المصادقة: JWT + Refresh Token Rotation + Argon2 + 2FA إلزامي لـOWNER.
- نظام صلاحيات OWNER كامل، مقفل على مستوى API لا الواجهة فقط.
- خط أنابيب الاستيراد الكامل (جمع → تطبيع → كشف تكرار → تحقق مصدر/حقوق → مراجعة بشرية → نشر) بلا نشر تلقائي.
- خدمة مراجعة عامة (ModerationService) تمنع النشر بلا مصدر أو بوسائط حقوقها غير واضحة.
- البحث العربي (FTS + pg_trgm + تطبيع كامل يتجاهل التشكيل/الهمزات/التطويل).
- نموذج القصيدة البنيوي: نسخ/أبيات/اختلاف روايات/نسبة الشاعر.
- حذف الحساب (فعلي لا Soft Delete وحده) وتصدير البيانات.
- تكامل MinIO فعلي لرفع الوسائط (فحص نوع/حجم + روابط موقَّعة).
- لوحة إدارة مكتملة بكل وحداتها: محتوى، مستخدمون، استيراد، اقتراحات، سجلات، المصادر، الحقوق، العلاقات، الإعدادات، التحليلات، النسخ الاحتياطية.
- CI كامل يغطي قائمة القسم 26 (كان موجودًا جزئيًا من قبل، أُصلح Lint المعطَّل عبره وأُضيفت فحوصات الهجرات/الأمان/الأسرار/Flutter analyze).
- النسخ الاحتياطي/الاستعادة (سكربتات تشغيلية عمدًا لا HTTP، مُتحقَّق منها حيًّا: نسخ → استعادة → مطابقة بيانات).
- ثغرة npm audit الحرجة الوحيدة (Next.js) أُصلحت بترقية تصحيحية آمنة (14.2.5 → 14.2.35).
- تسجيل الدخول/الحساب/التصدير/الحذف/السياسات مربوطة فعليًا بالموقع العام (كانت API فقط بلا أي واجهة تستخدمها).
- إصلاح خلل حقيقي: لوحة الإدارة لم تكن تتعامل مع تحدي 2FA إطلاقًا — كان مالك النظام عمليًا عاجزًا عن الدخول من نموذج الدخول نفسه.
- أول اختبارات حقيقية لـapps/web وapps/admin (90 اختبارًا إجمالاً في المستودع الآن) — تركّزت على تدفقات المصادقة حيث وُجدت أخطاء فعلية.
- تطبيق Flutter وُسِّع من 4 شاشات إلى ~40 شاشة حقيقية مربوطة بالخادم: شعراء/قصائد بنموذجها البنيوي الكامل/قصص/كتب/أمثال/مفردات/أماكن/موضوعات/مفضلة/أسئلة/حساب/إشعارات/سياسات/الخيل/الإبل/الصقارة والقنص/كلاب الصيد/المكتبة/الوسائط. أُصلح خلل حي حرج (عنوان API كان يعمل لأندرويد فقط لا iOS).
- تحقق حي شامل على محاكي iOS فعلي يغطي الحالات المصادَق عليها أيضًا (لا القراءة العامة فقط) — المفضلة والوسائط تعرضان بيانات حقيقية أُنشئت فعليًا عبر الـAPI في مراحل سابقة، ما يثبت الدورة الكاملة من قاعدة البيانات إلى واجهة iOS.
- بناء Xcode Cloud فعلي (رقم 4) نجح بلا أي خطأ ضد آخر كوميت — أُنتج Build مؤهل لمتجر التطبيقات فعليًا (لم يُقدَّم لمراجعة Apple).

- تصنيف الشعر متعدد الأبعاد (نوع الشعر/العصر/الغرض/المنطقة/الأداء/المجموعات) — 25 تصنيفًا مزروعًا، قابلة للإضافة والتعديل والترتيب والإخفاء والدمج والتفريع من لوحة المالك، ولا نوع شعر واحد مكتوب في أي واجهة.
- مكتبة الشاعر: نص/صوت/فيديو/صورة/وثيقة/رابط، بتبويبات تُبنى من الخادم ولا تظهر فارغة، مع عرض دقة التواريخ وملاحظة اختلاف المصادر.
- بوابة الحقوق: لا نشر لأي وسائط ما لم تسمح حالة حقوقها **و** يكن العرض مسموحًا — مفروضة على الخادم ومختبرة حيًّا بكل حالاتها.
- العضويات المهنية (راوٍ/مؤرخ) بثماني حالات، بفصل تقني صارم بين البيانات العامة وبيانات التحقق الخاصة، وموافقة صريحة محفوظة بنصها وإصدارها ونطاقها، وسحب الموافقة يوقف العضوية تلقائيًا.
- صلاحيات الراوي والمؤرخ: الإضافة فقط. لا نشر ولا اعتماد ولا تعديل حقوق ولا تعديل مادة مساهم آخر (مُثبت حيًّا بـ403 لكل حالة).
- تسع وثائق سياسات قابلة للتحرير من لوحة المالك بنظام إصدارات لا يكتب فوق النص السابق (الشروط بـ17 بندًا، واتفاقية المساهم بـ12 إقرارًا).
- رفع ملفات مواد المكتبة من داخل التطبيق (تُخزَّن خاصة دائمًا حتى تُراجع وتُحدَّد حقوقها)، وشاشة إضافة مادة بلا أي حقل حقوق أو نشر.
- تبويب «اختلاف الروايات» يعرض كل الروايات معًا مع موضع الاختلاف ومستوى التوثيق، دون ترجيح إحداها.
- صفحات الموقع العام: أقسام الشعر، قصائد القسم، ومكتبة الشاعر بتبويباتها.
- تنبيهات آلية في مسار المراجعة (تكرار محتمل، مصدر ناقص، حقوق غير مضبوطة) — مساعدة لا تحجب النشر، والقرار للمالك.
- هوية بصرية موحّدة "المجلس" (نجدية، بنّي عميق وذهب معدني) على كل شاشات تطبيق الجوال الـ45 بلا استثناء، بدعم كامل للوضع الليلي/النهاري/حسب إعدادات الجهاز، محفوظ الاختيار محليًا — بما فيه إثبات آلي (4 اختبارات) أن الاختيار اليدوي يتجاوز إعداد الجهاز فعليًا.

## قيد التنفيذ / التالي مباشرة

- توسيع تغطية اختبارات apps/web وapps/admin وapps/mobile لبقية الصفحات (بداية حقيقية موجودة، ليست تغطية شاملة).
- مشغّل صوت/فيديو فعلي داخل التطبيق (المواد تُعرض ببياناتها وروابطها، والتشغيل يحتاج حزمًا جديدة ومحتوى كافٍ للاختبار).
- إعادة روابط موقّعة جاهزة لوسائط مكتبة الشاعر بدل مفاتيح التخزين.
- **مراجعة محامٍ مرخّص في المملكة لوثيقة الشروط، خصوصًا بند النظام المختص — شرط قبل الإطلاق، والنص الحالي مسودة تشغيلية صراحةً.**

## لم يبدأ بعد

- إعادة هيكلة Monorepo إلى pnpm/Turborepo (قرار مُتعمَّد بعدم التنفيذ حاليًا — انظر IMPLEMENTATION_PLAN.md).
- توسّع بقية صفحات الموقع العام (18 صفحة SSR مطلوبة، الحساب/السياسات مكتملة، بقية أنواع المحتوى تحتاج نفس عمل Flutter).
- **استيراد بيانات تراثية حقيقية من مصادر خارجية (بانتظار تحديد المستخدم للمصدر) — الفجوة الأهم الآن فعليًا**، لأن أغلب الشاشات جاهزة تقنيًا لكن بمحتوى seed تجريبي لا تراث حقيقي موثَّق.
- النسخ الاحتياطي الآلي المجدوَل (Cron) في بيئة إنتاج فعلية — لا توجد بيئة إنتاج بعد.
- ترقية NestJS 10→11 وNext.js 14→16 (قفزات إصدار رئيسية عالية الخطورة، تحتاج نافذة اختبار مخصصة) — تبقي 40 ثغرة npm audit متوسطة/عالية الخطورة (0 حرجة الآن) غير مُصلَحة، أغلبها في تبعيات أداة بناء تطوير محلية (`@nestjs/cli`) لا تُشحن للإنتاج.

## غير مخطط لهذه المرحلة (بقرار صريح من المستخدم)
