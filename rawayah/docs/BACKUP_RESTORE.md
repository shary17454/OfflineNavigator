# النسخ الاحتياطي والاستعادة

## القرار المعماري

النسخ الاحتياطي والاستعادة سكربتات تشغيلية (`scripts/backup.sh`،
`scripts/restore.sh`) تُشغَّل مباشرة من طرف يملك وصولاً للخادم، **وليستا
مسار HTTP في لوحة الإدارة**. السبب:

- الاستعادة عملية مدمِّرة (تحذف كل البيانات الحالية وتستبدلها). تعريضها
  كزر ويب يفتح احتمال تنفيذها بالخطأ أو دون صلاحية كافية.
- ملف النسخة الاحتياطية يحتوي محتوى قاعدة البيانات بالكامل، بما فيه هاشات
  كلمات المرور وأسرار المصادقة الثنائية — تنزيله عبر HTTP يفتح سطح هجوم
  إضافي بلا داعٍ حقيقي في هذه المرحلة.

لوحة الإدارة (`/backups`) تعرض التعليمات فقط ولا تُنفِّذ أي عملية بنفسها.

## النسخ الاحتياطي

```bash
npm run db:backup
```

ينفِّذ `pg_dump` داخل حاوية `postgres` عبر `docker compose exec`، يضغط
المخرجات، ويحفظها في `backups/rawaya-<الطابع الزمني>.sql.gz` (المجلد غير
مرفوع على Git — `.gitignore` يستبعد `backups/*.sql.gz`).

## الاستعادة

```bash
npm run db:restore -- backups/rawaya-<التاريخ>.sql.gz
```

يطلب كتابة "نعم" صراحةً للتأكيد قبل المتابعة (عملية مدمِّرة). لتخطي
التأكيد التفاعلي (سكربتات آلية فقط، ليس للاستخدام اليدوي):

```bash
npm run db:restore -- backups/rawaya-<التاريخ>.sql.gz --yes
```

## التحقق

جرى التحقق الحي التالي فعليًا (وليس ادعاءً نظريًا) أثناء بناء هذين
السكربتين:

1. تشغيل `scripts/backup.sh` ضد قاعدة بيانات التطوير الحية — نجح، أنتج
   ملف `.sql.gz` صالح (تحقُّق يدوي من محتواه: رأس تفريغ PostgreSQL صحيح).
2. استعادة نفس الملف داخل حاوية Postgres مؤقتة منفصلة تمامًا (غير قاعدة
   بيانات التطوير الحقيقية، تفاديًا لأي مخاطرة) — نجحت الاستعادة، وتطابقت
   أعداد الصفوف في الجداول الأساسية (`User`, `Poem`, `Source`) بين قاعدة
   البيانات الأصلية والمُستعادة.

## متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `POSTGRES_SERVICE` | `postgres` | اسم خدمة Postgres في docker-compose |
| `POSTGRES_USER` | `rawaya` | مستخدم قاعدة البيانات |
| `POSTGRES_DB` | `rawaya` | اسم قاعدة البيانات |

## نسخ إنتاجية آلية (غير منفَّذ بعد)

الجدولة الآلية الدورية (Cron) للنسخ الاحتياطي في بيئة إنتاج فعلية، ورفعها
لتخزين خارجي (S3/MinIO منفصل عن تخزين الوسائط)، غير منفَّذة بعد — لا توجد
بيئة إنتاج فعلية حاليًا (انظر `IMPLEMENTATION_PLAN.md`). السكربتان أعلاه
جاهزان للاستخدام اليدوي أو الاستدعاء من أي مجدوِل خارجي عند وجود بيئة
إنتاج حقيقية.
